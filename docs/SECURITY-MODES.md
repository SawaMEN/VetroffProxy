# Режимы безопасности VetroffProxy

## Доступность

| Режим | Статус | Механизм |
|---|---|---|
| `tls` | Реализован | Настоящий TLS 1.3: сертификат, SNI, NSS/Go/Necko; SPKI pin по выбору |
| `reality` | Не реализован | Требует полноценной совместимой реализации рукопожатия REALITY на клиенте и сервере |
| `faketls` | Не реализован | Требуется выбрать конкретную несовместимую с другими вариацию (MTProto FakeTLS или ShadowTLS) |

Параметр `--security` не заменяет `--transport` или `--engine`.
При отсутствии поля `security` в старом профиле используется действующий TLS.
Попытки выбрать неподдерживаемую схему отвергаются **до** подключения, без
небезопасного fallback или ложного обещания поддержки.

## Следующие этапы

1. REALITY: выбрать совместимую реализацию, проверить лицензию и интеграцию с
   Vetroff HTTP/2; хранить секреты только в конфигурации сервера, обмениваться
   проверяемым открытым идентификатором, запретить plaintext fallback.
2. FakeTLS: зафиксировать одну спецификацию, определить аутентификацию,
   допустимые TLS версии, реальные тестовые векторы и совместимость.
3. Для каждой реализации: клиент + сервер + линк + конфигурация + негативные тесты
   аутентификации + сертификаты/имена + downgrade/повторные пакеты + CI.
4. Полевое измерение поведения Firefox на реальных сетях; сходство ClientHello
   не доказывает неотличимость трафика.

См. также [настройки](FEATURES.md) и [диагностику](CONFIGURATION.md).
