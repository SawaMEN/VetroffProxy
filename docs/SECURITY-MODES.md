# Защита и транспорты

VetroffProxy использует настоящее внутреннее HTTPS/TLS 1.3 с проверкой
цепочки сертификатов, DNS-имени и опциональным SPKI pin.
Параметр `--security tls` относится только к внутреннему защищённому каналу.

ShadowTLS v3 — **отдельный внешний TCP-мост**, конфигурация которого
создаётся командой `vetroff shadowtls-config`. Он использует
оригинальный бинарник ihciah/shadow-tls и включённый v3 strict,
без разрешения wildcard SNI. Отдельный пароль хранится в файле 0600
и приватных JSON-конфигурациях, а не в аргументах процесса.

Vetroff продолжает проверять сертификат сервера и SPKI pin за этим мостом.
Он подходит для TCP-транспортов (H2 CONNECT/POST, WSS и XHTTP), но
не для нативного HTTP/3/QUIC. Внешний TLS отпечаток формируется
ShadowTLS, а не Gecko/Necko.

Нельзя включить внешний мост одним `--security shadowtls-v3`: этот параметр
явно отклоняется. Вместо него используются подготовленные JSON-конфигурации
для `shadow-tls` и локальный `connection-local.txt`.
